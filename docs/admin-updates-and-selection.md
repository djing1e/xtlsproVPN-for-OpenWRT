# Тестовая версия 1.2.0-r1

## Подписка

Панель получает только признак наличия подписки и несекретные настройки заголовков.
Сохранённый URL не возвращается через новый RPC и не заполняет HTML/DOM. Пустое
поле сохраняет текущий URL; введённый URL заменяет его и очищается из поля после
отправки. Приложение больше не запрашивает и не предоставляет через свой ACL
прямое чтение/запись UCI `forkop_xray`. Конфигурация сохраняет права 0600.

Это защита от копирования сохранённой ссылки из панели, а не DRM против владельца
root-доступа. Root может прочитать файл, память процесса и импортированные ключи
узлов. Для ограничения раздачи необходима серверная политика: отдельная подписка
роутера, обязательный учёт HWID, лимит устройств и управляемый администратором
сброс регистрации. Один только передаваемый HWID не является криптографическим
доказательством устройства: администратор клиента может его подменить. Серверная
политика в этом PR не изменяется.

## NetBird

Статус подключения выделен зелёным. Кнопка проверки обновляет подписанный каталог
OpenWrt, сравнивает версию установленного пакета с доступной, затем разрешает
обновление конкретной версии. `apk add --upgrade netbird=VERSION` не использует
`--allow-untrusted` и не выполняет общее обновление системы. Версия в OpenWrt
может отставать от GitHub-релизов NetBird; произвольные upstream-бинарники не
подменяют установленный пакет.

Перед обновлением проверяются 32 МиБ MemAvailable и 24 МиБ свободного overlay.
Это предварительные пороги, не гарантия фактического пика. Стандартная директория
регистрации `/root/.config/netbird` архивируется с правами 0600 в приватный каталог
RAM `/var/run/xtlspro-netbird`. Служба наблюдения приостанавливается на время
операции. Сохраняется прежний режим автозапуска. Для ранее подключённого клиента
проверяется подключение к тому же management endpoint после перезапуска.

Обновление кратко прерывает административный туннель. Logout и повторный вход с
setup key не выполняются. Конфигурация Xray, DNS, firewall и маршрутов не меняется.
Откат версии пакета не заявляется: если повторное подключение не подтверждено,
операция возвращает ошибку и сохраняет резерв регистрации для диагностики.

## Переключение из панели

При работающем Xray выбор узла меняет override `fx_main` через RoutingService API
на 127.0.0.1:8080. Firewall, DNS и процесс Xray не перезапускаются. Сохранение UCI
и runtime-конфига происходит после проверки HTTPS через отдельный SOCKS выбранного
узла. При ошибке возвращается прежний API override. Изменение транспорта или
других полей работающей конфигурации не применяется этим путём.

Для возврата из ручного режима в полный автовыбор используется внутренний loopback
outbound `fx_auto` и отдельный leastPing-балансировщик `fx_auto_pool`. Это позволяет
не переписывать весь набор правил через API и не загружать геобазы заново.
Сохранённый ручной выбор остаётся штатным при следующем запуске Xray.

Открытые соединения продолжают использовать прежний outbound. Перенести TCP-сессию
с отказавшего сервера на другой сервер с иным выходным адресом нельзя.

## Фоновый автовыбор: причина ещё проверяется

Пользователь подтвердил разрыв при самостоятельной смене сервера в фоне. Перезапуск
из панели не объясняет этот случай. Сам leastPing Xray выбирает outbound при
маршрутизации новых соединений; его выбор не закрывает уже открытые handlers.
Алгоритм фонового leastPing в этой версии не заменён и исправленным не объявляется.

Монитор сохраняет до 40 событий в RAM: смена выбранного узла при прежнем PID либо
смена PID, время, режим, последнее состояние health и причина watchdog. История
доступна в `xray-lab-control status` как `selection_history` и в приватном файле
`/var/run/xray-lab-control/selection-events.json`. Интервал наблюдения — 15 секунд,
поэтому очень короткие изменения между опросами могут не попасть в историю.

При повторении разрыва нужны status, эта история и журнал watchdog. Они позволят
проверить отказ узла, перезапуск ядра и смену выходного IP без остановки процесса.

## Проверки перед выпуском

Тесты настоящего ucode с изолированными UCI и командами проверяют закрытый RPC
подписки, блокировки, обновление/ошибку подписи/нехватку RAM NetBird, сохранение
регистрации и автозапуска, ошибки переподключения, API-переключение и возврат старого
выбора после ошибки HTTPS или неопределённого результата RPC. Нативный генератор
проверен без запуска бинарника Xray: между выбором узлов меняется только основной
балансировщик; loopback-маршрут сохраняется с профилем RoscomVPN.

Нужна аппаратная проверка новой сборки: длительная загрузка при ручной смене узла,
возврат в auto после ручного старта и перезагрузки, обновление NetBird с локальным
доступом к роутеру и воспроизведение фонового разрыва с журналом событий.
