# Обновление приложения через LuCI

Разработка **1.1.1-r1**, после стабильного v1.1.0. Новый пункт меню:
**Services → xtlsproVPN → Обновление приложения**.

1. Нажмите «Проверить обновление». Проверяется последний стабильный релиз
   `djing1e/xtlsproVPN-for-OpenWRT`; draft и prerelease не используются.
2. Сверьте установленную и доступную версии, откройте описание релиза.
3. Нажмите «Установить обновление» и подтвердите установку конкретной версии.
4. Дождитесь проверки и обновите страницу браузера. При перезапуске rpcd интерфейс
   повторяет чтение статуса; установка выполняется отдельной службой procd.

Понижение и повторная установка той же версии запрещены. Автоматической установки
по расписанию нет. Ядро Xray и NetBird не обновляются вместе с приложением.
Для появления этого меню на r5 требуется одна первоначальная ручная установка APK.

## Что проверяется

HTTPS для всех переходов загрузки, фиксированный репозиторий и адреса файлов,
версия и архитектура/OpenWrt из манифеста, размер и SHA-256 APK. Дайджест манифеста
и APK сверяется с GitHub Release API. Это не подпись APK: доверие основано на HTTPS
и официальном репозитории, как у существующих установщиков.

Установка требует как минимум 24 МиБ `MemAvailable`, 12 МиБ свободного `/tmp`,
а во flash — установленный размер приложения из манифеста плюс 8 МиБ и место для
резервной копии. Эти ограничения не заменяют проверку реального потребления на
конкретной модели. Swap не прибавляется к доступной физической памяти.

Проверка релиза и установка блокируют параллельные операции Xray/NetBird.
Перед установкой создаётся приватный `/etc/xtlspro-update/backup.tar.gz`:
`/etc/config`, `/etc/forkop-xray` и `/etc/netbird`, если каталоги существуют.
Копия содержит секреты, имеет права 600 и не выдаётся через RPC. Следующее
обновление заменяет её новой копией. Бинарник Xray не копируется; его хеш
проверяется до и после установки.

APK устанавливается штатно с сохранением conffiles. Затем проверяются версия,
сохранение включённого/выключенного состояния прокси, HTTPS, DNS UDP/TCP,
перехват LAN и подключение NetBird, если оно было установлено до обновления.
Автоматический откат APK не реализован. При ошибке статус сообщает об этом;
резервная копия конфигурации остаётся во flash. При прерывании питания состояние
помечается как прерванное после загрузки. Это не гарантирует восстановление
самого пакетного менеджера после обрыва записи flash.

## Выпуск совместимого релиза

Actions собирает APK, `SHA256SUMS` и `update.json`. Манифест создаётся командой:

```sh
python3 scripts/make-update-manifest.py dist/xtlsprovpn-VERSION.apk --output dist/update.json
```

Вместо `VERSION` указывается полная версия, например `1.1.1-r1`.
При публикации проверенного артефакта нужно загрузить **все три файла** в один
стабильный релиз с тегом `v1.1.1`. SHA-256 и размер в манифесте относятся к
опубликованным байтам APK. Поле `installed_size_kb` — верхняя оценка размера
установленных файлов приложения; для текущего пакета задан запас 4096 КиБ.
Зависимости устанавливает APK, нехватка места на них возвращается как ошибка.

Старый v1.1.0 без манифеста корректно отображается как уже установленный/более
старый. Новый релиз без подходящего манифеста к установке не предлагается.

## Аппаратная проверка перед стабильным выпуском

Проверить на LAB переход на следующий тестовый APK: перезапуск rpcd во время
установки, восстановление UI, сохранность подписки/HWID/NetBird, включённый и
остановленный прокси, работу HTTPS/DNS с телефона. Отдельно проверить отказ при
нехватке места и восстановление после обрыва питания во время установки APK.
Локальные тесты используют изолированный пакетный менеджер и не заменяют эти
проверки на OpenWrt/procd.
