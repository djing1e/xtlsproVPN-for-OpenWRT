# Проверка подписки на роутерах с 256 МБ RAM

Тестовая версия **1.1.2-r1**, после стабильной 1.1.1-r2.

На клиентском WR3000S с Xray и NetBird обновление подписки отклонялось:
`Not enough RAM for isolated candidate testing; live state retained.`
Свободно было около 53 МиБ, а полный проверяющий процесс требовал 96 МиБ.
Рабочая конфигурация при отказе сохранялась.

Новый планировщик предварительной проверки:

1. Полная конфигурация кандидата проверяется установленным Xray (`run -test`),
   шаблон firewall проверяется nftables, как прежде.
2. Каждый новый или изменённый узел проверяется отдельным последовательным
   процессом: один исходный outbound, минимальные loopback-входы и правила DNS.
   Клиентские геоправила, observatory, API и статистика не загружаются.
3. Отдельно проверяется HTTPS через узел из выбранного пула и DNS кандидата.
   При автовыборе предпочитается узел со свежим положительным observatory;
   без свежих данных используется первый узел выбранного пула. Обход клиентской
   политики исключает ложную успешную проверку через DIRECT.
4. Одновременно работает только один проверяющий процесс. Его GOMEMLIMIT —
   24 МиБ, минимальный MemAvailable — 32 МиБ. Это мягкий лимит Go, а не предел RSS.
   Проверяющий процесс получает повышенный oom_score_adj; в журнале фиксируется
   его VmRSS/VmHWM. Значения нужно проверить на реальном роутере.
5. Затем сохраняется прежняя проверка работающего соединения, журнал применения,
   перезапуск при изменениях, проверка HTTPS/DNS/перехвата LAN и откат при сбое.

Если минимальная конфигурация содержит ссылки на DNS-геобазы, неподдерживаемый
балансировщик или зависимости outbound за пределами проверяемого графа,
используется прежняя полная проверка с порогом 96 МиБ. Отказ не разрешает
применение без предварительной проверки. Последовательная проверка не изменяет
полный профиль маршрутизации, который будет применён после проверки.

В UI и состоянии расписания теперь выводится конкретная причина отказа,
включая требуемую и доступную RAM. Логи с URL подписки в RPC не передаются.
Кнопки освобождаются, если исходное задание было заменено другим и backend
подтверждает отсутствие активной операции и блокировки.

## Проверки

Локальные тесты: построение минимального графа, изменение транспортов, ручной
выбор и автовыбор, сохранение DNS bootstrap и направления через прокси,
возврат к полной проверке для сложных зависимостей, последовательное выполнение
при 48 МиБ доступной памяти в изолированной модели, отклонение недоступных
кандидатов, нехватки памяти и неработающего DNS, прежние сценарии отката,
освобождение кнопок и отсутствие секретов в сообщениях.

Нужна аппаратная проверка: обновление подписки с активными Xray/NetBird на
WR3000S, измерение VmRSS/VmHWM, сохранение доступа и маршрутизации. Стабильный
релиз 1.1.1-r2 пока остаётся основным.
