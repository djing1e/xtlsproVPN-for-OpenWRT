## Платформа

Проверено на **Cudy WR3000U v1 и WR3000S v1 / OpenWrt 25.12.5 / mediatek/filogic / aarch64**.
Это APK приложения, не образ прошивки. Ядро Xray и базы скачиваются отдельно;
пользовательские подписки, ключи и пароли не включены в пакет.

Возможности: VLESS/REALITY/XHTTP, выбор узла и автовыбор, доменные и IP-правила
PROXY/DIRECT/BLOCK, профили маршрутизации, DNS/DoH/DoT, TTL, QUIC, watchdog,
обновления по расписанию, установка и откат официального ядра.
IPv6-перехват не реализован. Точная конфигурация испытаний и оставшиеся проверки
указаны в протоколе; остальные модели не объявляются проверенными.

## Установка

Две команды для OpenWrt 25.12.5 / aarch64. Выполняйте по SSH от root.

**1. Чистая установка** — если пакет xtlsproVPN ещё не установлен:

```sh
clear; wget -O /tmp/xtls-install.sh https://raw.githubusercontent.com/djing1e/xtlsproVPN-for-OpenWRT/main/install.sh && sh /tmp/xtls-install.sh
```

**2. Обновление** — для уже установленного пакета, с сохранением настроек:

```sh
clear; wget -O /tmp/xtls-update.sh https://raw.githubusercontent.com/djing1e/xtlsproVPN-for-OpenWRT/main/update.sh && sh /tmp/xtls-update.sh
```

Оба установщика проверяют платформу и SHA-256 APK. Чистая установка не удаляет
старую установку, а предлагает ссылку обновления. Обновление использует штатный
механизм APK без удаления конфигурации и ядра; при актуальной версии завершается
без переустановки, понижение версии запрещено. Ядро Xray управляется отдельно
из интерфейса. При фактическом обновлении пакета возможен краткий перезапуск
прокси штатным обработчиком APK.

APK релиза устанавливается как локальный пакет с `--allow-untrusted`.
Постоянный ключ доверенного репозитория пакетов пока не распространяется.
Зависимости берутся из настроенных репозиториев OpenWrt.

В LuCI откройте **Services → xtlsproVPN → Настройки**:

1. На вкладке **Ядро** установите выбранную официальную версию. Проверенная
   базовая версия — 26.7.28; upstream помечает её как prerelease, соответствующий
   фильтр включён по умолчанию. Проверка совместимости предшествует установке.
2. Сохраните URL подписки, обновите подписку и профиль маршрутизации.
3. Если интернет приходит через LAN, выберите **lan** как интерфейс наблюдения
   watchdog; обычное значение по умолчанию — **wan**.
4. Выключите flow offloading в firewall, если он включён, и запустите прокси.
5. При необходимости настройте DNS и расписание. Cron использует время роутера.

До первого явного запуска перехват клиентов не включается. LAN/DHCP установщик
не перенастраивает. Чистая установка APK и первое ядро из UI проверены на r4;
обновление r4 → r5 и дальнейший цикл испытаний выполнены на том же LAB.

При отсутствии доступа к GitHub можно перенести оригинальный архив и дайджест
Xray с ПК и использовать штатный bootstrap:

```sh
xtlspro-core-bootstrap 26.7.28 /tmp/Xray-linux-arm64-v8a.zip /tmp/Xray-linux-arm64-v8a.zip.dgst
```

## Обновление существующей установки

Conffiles сохраняются при штатном обновлении APK. Проверен переход r4 → r5;
импорт произвольных старых файловых LAB-сборок автоматически не выполняется.
Начиная с 1.1.1 доступен пункт **xtlsproVPN → Обновление приложения**:
проверка стабильного релиза и установка по кнопке. Версия, платформа, размер и
SHA-256 проверяются перед установкой; конфигурация сохраняется в приватную
резервную копию. Для перехода с 1.1.0-r5 на версию с этим меню используйте
команду обновления выше. Ядро Xray и NetBird управляются отдельно.

Переход с 1.1.1-r1 с исправлением определения версии на **1.1.1-r2** через UI
проверен на HOME: настройки сети, DHCP, DNS и Xray и бинарник ядра сохранились,
HTTPS через прокси и существующий NetBird работают. Автоматического отката APK
нет; восстановление после обрыва питания во время установки APK ещё не проверено.
Подробнее: [обновление приложения](docs/package-updates.md).

При обновлении подписки кандидат проверяется отдельно от работающего процесса.
Ошибки до применения оставляют рабочее состояние, ошибки после применения
вызывают откат. Незавершённое применение подписки восстанавливается из одного
приватного журнала во flash при загрузке, в том числе при выключенном прокси;
само восстановление прокси не включает. Это не журнал установки APK или ядра.

Для схемы с общим клиентским интерфейсом и основным uplink служба отключает
отправку ICMP redirects. Защита действует и при остановленном прокси, чтобы
клиенты не запоминали путь в обход выбранного шлюза. Исходные значения
возвращаются при остановке службы `xray_lab_recovery` или смене схемы при
следующем применении настроек, если администратор не изменил их после запуска.

## Доступ, идентификаторы и ресурсы

Доступ к настройкам использует штатную аутентификацию LuCI/rpcd. Пользователь с
root SSH или root-паролем может менять настройки; отдельного пароля вкладки нет.
ACL `xtlsprovpn-viewer` предоставляет только статус/диагностику, не создаёт
аккаунты и не является готовым отдельным интерфейсом клиента. Проверки прав
отдельного ограниченного аккаунта ещё не завершены.

Отправка HWID включена: при первом обращении к подписке создаётся постоянный UUID
роутера; пользовательский HWID и URL изначально пусты. Заголовок:
`xtlsproRouter(id:UUID)`. Совместимость с любым серверным алгоритмом HWID Happ
не заявляется. Идентификатор не следует копировать между устройствами.

Журнал соединений выключен по умолчанию. Журналы находятся в RAM; монитор
периодически сокращает файлы больше 1 МиБ до последних 100 строк. Это не жёсткая
квота. Настройки, HWID и журнал восстановления подписки находятся во flash;
состояния фоновых операций — в RAM. Последнее состояние установки APK и её
резервная копия конфигурации сохраняются во flash. По умолчанию резервное ядро удаляется после
успешной проверки, настройка хранения доступна отдельно.

Во втором релизе доступен NetBird для self-hosted сервера. Агент устанавливается
отдельно из вкладки «Административный доступ»; подключение — через setup key.
DNS и маршруты NetBird отключены. SSH/LuCI доступны через адрес NetBird.
Подробности и расход ресурсов: [NetBird](docs/netbird-admin.md).

## Сборка и проверки

Workflow **xtlsproVPN ARM64 package (development)** собирает APK в закреплённом официальном
SDK OpenWrt 25.12.5 с проверкой SHA-256. Ручной запуск доступен через Actions →
Run workflow. Локальная сборка на Linux x86_64 с зависимостями SDK:

```sh
python3 scripts/check-source.py
bash scripts/build-sdk.sh
```

Готовый artifact содержит APK, `SHA256SUMS` и `update.json` для обновлений через UI. Исходный код, тесты, лицензии и
атрибуция сохранены. В аппаратных тестах использованы синтетические изменения;
рабочие подписки и учётные данные не публикуются.

Стабильный релиз публикуется отдельным workflow из проверенного Actions-артефакта
после проверки исходников пакета и контрольных сумм. Коммит выпуска с заголовком
`Release v…` пропускает повторную SDK-сборку, поскольку публикует тот же APK.


В v1.1.0 проверены обновление с v1.0.0, NetBird и восстановление подключения
после перезагрузки, DoH через прокси на WR3000S с 256 МБ RAM и ZRAM 128 МиБ,
DNS UDP/TCP и TTL 60. Проверенная базовая версия Xray — 26.7.28.
В v1.1.1 добавлено и проверено обновление APK через UI.
В v1.2.0 исправлено обновление подписки на роутерах с 256 МБ RAM и работающим
NetBird: последовательные проверки используют минимальные конфигурации Xray.
На Dimarouternew обновление прошло при 50 560 КиБ доступной RAM; проверочный
Xray занял 25 560 КиБ RSS/HWM. HTTPS, DNS UDP/TCP с TTL 60 и NetBird сохранили
работоспособность; диагностика LuCI — 26/26 без ошибок.
[Подробности проверки памяти](docs/low-memory-subscription.md).

В v1.3.0 добавлены guard NetBird и аварийный обратный SSH через встроенный Dropbear.
Резерв выключен по умолчанию, настраивается отдельно для каждого роутера и открывается
через пять минут отказа NetBird. После восстановления остаётся ещё десять минут.
Проверены обновление и перезагрузка HOME, сохранение ключа, ручное управление и восстановление туннеля.

В v1.4.0 добавлены Telegram-управление роутерами и регистрация устройств на VPS:
постоянный UUID, публичный профиль, проверка обоих SSH-каналов, отдельные аварийные
учётные записи и порты, сохранение клиентских привязок и зашифрованные копии.
На LAB проверены регистрация без дубликатов, переключения локаций и каналов,
перезагрузка и refresh обработчиков без смены PID Xray. APK содержит публичные
обработчики; программа бота на VPS устанавливается и обновляется отдельно.
Клиентские токены, профили и приватные ключи в APK не входят.
