# xtlsproVPN 1.0.0 — кандидат для чистого OpenWrt

Исходники пакета для OpenWrt 25.12.5, mediatek/filogic, ARM64. Рабочие функции проверены на Cudy WR3000U v1; установка SDK-пакета на чистое устройство ещё требует проверки. Это не образ прошивки и не готовый APK.

## Что входит

Подписки VLESS/REALITY/XHTTP, личные правила маршрутизации, DNS/DoH/DoT, TTL, QUIC, мониторинг, расписание, выбор версии ядра. Функции ядра зависят от выбранного официального релиза; конфигурация проверяется перед применением.

На чистой установке подписка и собственный HWID пустые. Отправка HWID включена: при первом обращении к подписке создаётся отдельный постоянный UUID, заголовок — `xtlsproRouter(id:UUID)`. Копировать идентификатор между роутерами не нужно. User-Agent Happ сохранён для совместимости подписок. Учёт устройства определяется сервером подписки; универсальная совместимость с любым HWID-алгоритмом Happ не заявляется.

Расписание выключено до настройки. Прокси не перехватывает трафик до явного запуска. Нет жёстко заданных адресов LAN, серверов подписки, пользовательских ключей или учётных записей. Обычный интерфейс наблюдения по умолчанию — WAN; для схемы с интернетом через LAN выберите LAN. Старая расширенная страница не включена.

Ядро и базы не встроены в пакет. Первое ядро 26.7.28 устанавливается отдельной командой с официального GitHub с проверкой SHA-256, извлекается только `xray`. После настройки ядра обновляются выбранной версией из UI с проверкой и откатом. На чистой установке туннеля для резервного скачивания ещё нет: при недоступном GitHub используйте официальный архив/дайджест, перенесённые с ПК. Версия 26.7.28 обозначена upstream как prerelease, поэтому соответствующий фильтр включён по умолчанию.

Данные маршрутизации скачиваются отдельно после первого запуска. Имена технических служб и конфигураций сохранены ради совместимости; интерфейс называется xtlsproVPN. В исходниках сохранены лицензии и указание происхождения кода.

## Сборка APK

Распакуйте исходники в корень нового GitHub-репозитория, откройте Actions → xtlsproVPN 1.0.0 ARM64 package → Run workflow. Сборка также запускается при отправке изменений в main. Workflow скачивает закреплённый официальный SDK OpenWrt 25.12.5 и проверяет его SHA-256, затем собирает пакет. Результат — artifact с APK и SHA256SUMS. Публикация release автоматически не выполняется. Ключи подписи/доступа в репозиторий не включены.

Локально на Linux x86_64 с зависимостями OpenWrt SDK:

```sh
clear
bash scripts/build-sdk.sh
```

Точная версия SDK и checksum находятся в scripts/build-sdk.sh. Если SDK недоступен, сборка завершается ошибкой, без выдачи фиктивного APK. Первый запуск GitHub-сборки и установка APK пока не подтверждены.

## Первая установка на чистый тестовый роутер

Проверьте SHA256SUMS скачанного artifact на ПК. Для локального APK собственной сборки:

```sh
clear
apk update
apk add --allow-untrusted /tmp/xtlsprovpn-1.0.0-r1.apk
xtlspro-core-bootstrap 26.7.28
```

Имя APK возьмите из artifact (SDK может включить архитектуру в имя). `--allow-untrusted` относится к локальному пакету вашей сборки; зависимости берутся из настроенных репозиториев OpenWrt. Для тиражирования нужны постоянная подпись пакетов и доверенный ключ на устройствах.

Если GitHub недоступен, передайте на роутер оригинальные Xray-linux-arm64-v8a.zip и Xray-linux-arm64-v8a.zip.dgst одной версии:

```sh
clear
xtlspro-core-bootstrap 26.7.28 /tmp/Xray-linux-arm64-v8a.zip /tmp/Xray-linux-arm64-v8a.zip.dgst
```

Далее Services → xtlsproVPN → Настройки → Подписка: укажите URL, сохраните. На дашборде обновите подписку, затем запустите прокси. До активации отключите flow offloading в firewall, если он включён. Менять адрес LAN/DHCP или сеть для установки не требуется. После рабочего запуска можно включить расписание и обновить списки маршрутизации командой xray-lab-routing update.

Установка поверх файловой LAB-сборки автоматически не поддерживается: сначала проверяется чистый тестовый роутер. Не обнуляйте подписку на действующих устройствах ради обновления. Conffiles сохраняются при обычном пакетном обновлении.

## Доступ администратора

Настройки доступны через штатную аутентификацию LuCI/rpcd. Пароль root должен оставаться у администратора. Пользователь, знающий root-пароль или имеющий root SSH, может менять любые настройки; отдельный пароль вкладки этого не исправляет.

В пакет включён ACL xtlsprovpn-viewer только для чтения статуса/диагностики, без UCI, shell и записывающих методов. Он не создаёт аккаунт и не задаёт пароль. Для пользователя нужна отдельная учётная запись rpcd без wildcard `*`, файловых и командных прав и без write-ролей проекта. Существующие root/rpcd аккаунты установщик не меняет. Штатная страница настроек требует административной роли; полноценный отдельный UI для viewer в этот выпуск не входит. Пароли и NetBird настраиваются отдельным этапом.

## Логи и ресурсные ограничения

Журнал соединений выключен по умолчанию. Ошибки warning пишутся в RAM; монитор сокращает журналы больше 1 МиБ до последних 100 строк каждые 15 секунд. Это периодическое ограничение, а не жёсткая файловая квота. Подробный журнал соединений включайте для диагностики и затем выключайте. Состояния заданий и попыток обновления — в RAM; настройки и идентификатор устройства — во flash. Предыдущее ядро удаляется после успешных проверок по умолчанию.

## Проверки перед выпуском

- чистая установка APK, ввод новой подписки, первый запуск;
- перезагрузка, DNS UDP/TCP и TTL, HTTPS, телефон;
- PROXY/DIRECT/BLOCK, сохранение правил после обновления подписки;
- расписание и обновление/откат ядра;
- проверка отсутствия прав изменения у отдельного пользовательского аккаунта;
- измерение flash/RAM; затем фиксация стабильного v1.0.0.

В комплекте self-contained тесты синтетического каталога и HWID. Нужны ucode с fs и официальный тестовый Xray, путь XRAY_TEST_BIN можно задать окружением. Базовый check-source.py не требует Xray. Конфиденциальных данных рабочей подписки в тестах нет.


## 1.0.0-r4 — unified test build

Includes persistent LAN source-validation policy (with existing manual rules preserved),
short persistent HWID and router metadata, automatic Xray/version User-Agent,
manual subscription + routing refresh, and first core installation from LuCI.
The package contains neither a core executable nor customer subscriptions/geodata.
First core installation validates a minimal configuration and leaves the proxy stopped.
Install the selected core, enter a subscription, then refresh and start the proxy.
Hardware validation of cold installation and reboot persistence is still required;
this is a test build, not a confirmed stable release. IPv6 interception is not implemented.


## 1.0.0-r5 — восстановление подписки после прерывания

Перед публикацией изменений подписки сохраняется одна приватная резервная копия
конфигурации и каталога во flash. После перезапуска незавершённое применение
откатывается до генерации конфигурации Xray. Отдельная служба восстановления
работает и при отключённом автозапуске прокси; сам прокси она не запускает. После сохранённого решения commit
сохраняется новый каталог. Восстановление можно прервать и повторить; повреждённая
резервная копия блокирует автоматический запуск и остаётся для диагностики.
Журнал относится к применению подписки, а не к установке ядра или APK.
Системные DNS и firewall заново формируются штатной службой из восстановленной
конфигурации. Остановка пользователем по-прежнему отключает автозапуск.

Для схемы, где клиентский интерфейс одновременно указан в основном маршруте по
умолчанию, служба временно отключает отправку ICMP redirects (`all` и соответствующие
клиентские интерфейсы). При остановке возвращаются сохранённые значения, если
администратор не изменил их после запуска. Схема с отдельным WAN не требует
изменения этих параметров. IP-адрес тестового роутера в логике не используется.

Изолированные проверки: `test_recovery_journal.py`, `test_sync_transaction.py`,
`test_redirects.py`, `test_stop_safety.py`. Проверки SIGKILL моделируют потерю
процессов без EXIT-обработчиков; физическую устойчивость flash необходимо
проверить на тестовом роутере после сборки APK.
