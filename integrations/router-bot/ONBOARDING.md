# Подключение клиентских роутеров

Комплект входит в APK 1.4.0-r1. Установка APK сама не выдаёт доступ боту.
Telegram-токен и приватные ключи в пакет не входят. Для подключения нужен уже
настроенный роутер с работающими xtlsproVPN, NetBird и непустым паролем root.
Оператор выполняет подготовку перед передачей устройства клиенту.

## Один раз на VPS бота

Разместить актуальные `fleet.py` и `bot.py` в `/opt/xtls-router-bot/`,
`backup.py` в том же каталоге. Файлы принадлежат root, режим 644. Сохранить
существующие конфигурацию, токен, SQLite, SSH-ключ и known_hosts. После обновления
бота установить/проверить таймер `backup.py install`.

Создать публичный профиль из имеющихся ключей VPS и бота:

```sh
clear
python3 /opt/xtls-router-bot/fleet.py profile \
    --host PUBLIC_VPS_IP --port 62152 \
    --output /root/xtls-bot-profile.json
```

В профиле только публичный адрес, порт и открытые ключи. Один профиль можно
использовать для всего парка. Скопировать его на роутер как
`/tmp/xtls-bot-profile.json` через SFTP в административной SSH-сессии.

## На каждом роутере

Установить APK с проверкой SHA256, затем:

```sh
clear
xray-lab-bot prepare /tmp/xtls-bot-profile.json
```

Подготовка сохраняет постоянный UUID, добавляет ограниченный SSH-ключ бота,
устанавливает обработчики и создаёт аварийный ключ только при его отсутствии.
Существующие административные ключи остаются. Печатается строка
`xtls-enroll-v1:...`; дополнительно создаётся `/root/xtls-router-passport.json`.
Код содержит UUID, модель, адрес NetBird и открытые ключи. В нём нет ссылки
подписки, Telegram-токена и приватных ключей. Передавать код оператору через
доверенный канал: подмена публичных данных меняет первоначальное доверие.

## Зарегистрировать на VPS

```sh
clear
python3 /opt/xtls-router-bot/fleet.py enroll \
    --code 'xtls-enroll-v1:PASTE_CODE' --name 'Клиент · адрес установки'
python3 /opt/xtls-router-bot/fleet.py list
```

Альтернатива — передать публичный JSON через SFTP и использовать
`--passport /root/router-passport.json`. Для существующего LAB добавить
`--router lab`: сохранятся R-000001, история и выданные доступы. Не создавать
новую запись для того же LAB. Старый вручную созданный аварийный пользователь
сохраняется для отката; новая регистрация назначает отдельного пользователя.

VPS сверяет закреплённый SSH-ключ и UUID по основному каналу, назначает отдельные
учётную запись и свободный порт 22001–29999, проверяет ограничения sshd, затем
проверяет тот же роутер через аварийный туннель. Только после этого сохраняет
реестр и фиксирует регистрацию. При ошибке до фиксации восстанавливает прежние
настройки. При потере ответа на фиксацию сохраняет запись для повторной сверки.
Повторить тот же код безопасно: новые UUID, порты и дубликаты не создаются.

Регистрация кратковременно перезапускает только службу бота на VPS; активные
операции блокируют её. Интернет, NetBird и прокси роутера не перезапускаются.
После регистрации открыть карточку, проверить основной и аварийный каналы,
выдать Telegram-клиенту доступ кнопкой «Доступ клиентов». Номер подписки служит
для отображения; он не выдаёт право управления.

## Обновления, перенос и клонирование

Следующие APK обновляют публичные обработчики подготовленного роутера после
завершения текущей операции. UUID, профиль, ключи и доступы не заменяются.
Откат при частичной записи возвращает предыдущие обработчики. Без профиля APK
не активирует бота. `/etc/xtlspro-bot/` включён в список сохранения sysupgrade.

Не клонировать настроенные `/etc/xtlspro-bot/`, `/etc/xtlspro-rescue/` и серверные
ключи Dropbear на другое физическое устройство. Готовить каждый роутер отдельно.
Повтор UUID, адреса или управляемого SSH-ключа обнаруживается при регистрации.

Зашифрованная копия бота сохраняет реестр, привязки и инструмент fleet.py.
После восстановления и проверки SSH-ключа VPS команда `fleet.py rebuild-relay`
воссоздаёт ограниченных аварийных пользователей. SSH-сервер VPS, его приватные
host keys, NetBird и ОС в копию бота не входят. Изменение IP или host key VPS
требует отдельной миграции профилей роутеров; восстановление архива само по себе
не перенаправляет аварийные туннели на новый адрес. Старые архивы без fleet.py
по-прежнему поддерживаются. Архив и backup.key хранить вне VPS раздельно.

## Приёмка перед стабильным релизом

1. Подключить LAB через `--router lab`, сверить R-код и клиентские доступы.
2. Повторить регистрацию: записи и порты не дублируются.
3. Проверить карточку, выбор локации и отказ произвольной SSH-команды.
4. Проверить основной → аварийный → основной канал, затем перезагрузку.
5. Проверить сохранение UUID и ключей после следующего APK.
6. Проверить новый клиентский роутер и восстановление зашифрованной копии.

Автоматические тесты проверяют границы протокола, транзакции и комплект APK.
Они не заменяют эти проверки на физическом роутере и Debian VPS.
