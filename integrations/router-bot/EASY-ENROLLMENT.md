# Полуавтоматическое подключение: две команды

Для существующего VPS бота и настроенного клиентского роутера. На роутере нужны
xtlsproVPN 1.4.0+, работающий NetBird, доступный через него SSH и непустой пароль
root. Установка приложения или NetBird с нуля в этот мастер не входит.
Дополнительный HTTP-сервис, входящий порт и новый VPS не нужны.

## Один раз на VPS

Установить проверенный `server/setup-connect.sh` от root. Установщик скачивает
закреплённые версии файлов с проверкой SHA256, сохраняет копии старых инструментов
и зашифрованные копии бота, добавляет команду `xtls-router-add`.
Конфигурация, токен, SSH-ключ, known_hosts и работающая программа бота сохраняются.
Бот не перезапускается. Новые инструменты и команда включены в последующие
зашифрованные копии; прежние архивы остаются совместимыми.

## Для каждого роутера

**Команда 1 — на VPS бота:**

```sh
clear
xtls-router-add
```

Мастер покажет готовую блок команд. Скопировать его целиком и выполнить
в другой SSH-вкладке на нужном роутере — это **команда 2**. Профиль передаётся
автоматически как публичные данные внутри команды; скачивать файлы через ПК
или SFTP не требуется. Скрипт роутера загружается из закреплённого коммита и
проверяется по SHA256 перед запуском.

На роутере появится короткий код вида:

```text
xtls-pair-v1:NETBIRD_IP:SSH_PORT:PUBLIC_FINGERPRINT
```

Скопировать его и вставить в ожидающий мастер на VPS, нажать Enter. Пока мастер
ожидает код, это обычный ввод пользователя; SSH не завис. Роутер можно готовить
в другой вкладке без удержания общей блокировки регистрации.

После проверки мастер сам добавит запись, создаст отдельного аварийного
пользователя/порт и проверит основной и резервный каналы. Telegram-клиенту доступ
выдаётся отдельно кнопкой «Доступ клиентов»; знание номера подписки прав не даёт.

Необязательное имя задаётся сразу:

```sh
clear
xtls-router-add --name 'Клиент · место установки'
```

Если публичный профиль VPS ещё не создан, при первом запуске указать его IPv4 и
SSH-порт. Существующий профиль и его ключи мастер менять не разрешает:

```sh
clear
xtls-router-add --host PUBLIC_VPS_IP --port 62152
```

Повторная попытка с уже полученным кодом возможна без повторной подготовки:

```sh
clear
xtls-router-add --code 'xtls-pair-v1:NETBIRD_IP:SSH_PORT:PUBLIC_FINGERPRINT'
```

## Как проверяется устройство

Короткий код передаётся через доверенную административную сессию и содержит
адрес NetBird, SSH-порт и SHA256-отпечаток открытого серверного ключа. VPS получает
Ed25519-ключ через ssh-keyscan, сверяет его с кодом и лишь затем использует его
во временном known_hosts для полноценного SSH-входа и чтения публичного паспорта.
Один ssh-keyscan не считается подтверждением доверия. Отключение проверки
host key, пароль и автоматическое принятие чужого ключа не используются.

В паспорте дополнительно проверяются профиль VPS, UUID, адрес, порт и открытые
ключи. Существующий закреплённый ключ нельзя заменить автоматически. При
совпадении существующей записи сохраняются её внутренний ID, R-код и привязки;
UUID и ограничения аварийного пользователя дополнительно сверяет обычный fleet.py.
Повторы и откат используют тот же проверенный механизм регистрации.

Код и публичный профиль не содержат Telegram-токена, ссылки подписки, setup key
или приватных ключей. Тот, кто подменяет сам переданный оператору код, меняет
начальную точку доверия — копировать его нужно непосредственно с нужного роутера.
Изменения IP/ключей VPS и перенос на другую машину остаются отдельной миграцией.

## Проверки

Автотесты покрывают подготовку одной командой, неверный профиль/код/отпечаток,
сохранение known_hosts, совпадение паспорта, принятие существующей записи,
частичный сбой установки и восстановление мастера из зашифрованной копии.
Аппаратный прогон нового мастера начинается с повторного подключения уже
зарегистрированного LAB; первичная регистрация ещё одного физического роутера
проверяется отдельно. Старый путь с публичным JSON остаётся доступен в ONBOARDING.md.
